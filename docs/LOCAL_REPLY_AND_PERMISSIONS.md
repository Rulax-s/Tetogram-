# Tetogram 0.2.5: локальное представление ответа и разрешения

## Reply

Сетевой TL Message остаётся настоящей цитатой с mention исходного автора, как в 0.2.4. `messageOwner.message`, `entities`, `reply_to` не подменяются. Отдельные display-accessors MessageObject используются ChatMessageCell для штатной линии Reply, имени, сниппета и текста ответа. Обычные Reply проходят прежний путь. UI-заголовок никогда не записывается в owner и не сериализуется. Темы, размеры и отступы задаёт исходный ChatMessageCell.

`LocalReplies` добавляет таблицу `tetogram_reply_links_v1` в существующую SQLite-базу MessagesStorage: Telegram user ID, dialog ID, random ID, текущий message ID, namespace обычных/запланированных сообщений, исходный message/sender ID, UTF-16 смещение ответа, SHA-256 префикса. Текст оригинала повторно не сохраняется. При явной очистке удаляются также соответствующие связи. Подтверждение отправки обновляет ID по owner/dialog/random ID/namespace. При загрузке страницы связь соединяется с существующей таблицей архива и создаёт отдельный MessageObject исходника для каждого ответа. Данные автора берутся из штатного локального users/chats cache на storage queue и передаются UI без запроса истории с сервера. Аккаунт проверяется также перед UI callback. Порядок и stable ID строк не меняются.

Нажатие на Reply повторно проверяет архив и использует штатный переход с подсветкой. Очистка/истечение retention приводит к серверной цитате при обновлении, onResume, очередной минутной сверке или нажатии. Префикс проверяется по UTF-16 границе и хешу: изменённая цитата безопасно остаётся серверной. Редактирование/пересылка используют canonical wire view; координаты выбранного фрагмента ответа переводятся в серверный текст.

Связи создаются для новых отправок 0.2.5; старые цитаты 0.2.4 не сопоставляются по похожему тексту. Связи локальны: другой клиент и другое устройство видят серверную блок-цитату. Без текста ответа (пустая подпись) сохраняется серверное представление. Секретные/эфемерные сообщения не участвуют.

## Реальные дефекты проверок разрешений

- Отсутствовало READ_MEDIA_VISUAL_USER_SELECTED, а UI требовал одновременно полный доступ к изображениям и видео. Частичный доступ Android 14 и доступ к одному типу ошибочно считались отсутствием разрешения.
- Callback проверял только grantResults[0], поэтому selected-only grant мог показывать ошибку доступа.
- MediaStore-запросы фото/видео допускались по несвязанному разрешению audio. Теперь каждый запрос проверяет свой тип, partial grant оставляет фильтрацию выбранных файлов системе.
- Добавлена декларация selected permission и совместный запрос на Android 14+, проверка актуального OS состояния при открытии/resume галереи. Внешний выбор одного файла использует системный Photo Picker на Android 13+, встроенная галерея сохранена. Недоступный путь выбранного видео копируется штатным MediaController в кэш, null больше не передаётся редактору.
- Документам через SAF на Android 13+ не требуется полный доступ к фото/видео.
- Уведомления уже проверяли POST_NOTIFICATIONS. Найдены устаревающие отложенные проверки и доверие первому результату callback без повторной проверки OS. Теперь проверяются runtime grant и areNotificationsEnabled перед экраном/запросом и действием его кнопки; PermissionRequest также повторно читает OS grant. Каналы/звуки не меняются.

**Не установлено на устройстве:** отзывались ли действующие полные разрешения при обновлении APK. Код не доказывает это, и обновление само по себе не считается причиной. Совместимость временного partial grant объяснена Android: https://developer.android.com/about/versions/14/changes/partial-photo-video-access . Уведомления: https://developer.android.com/develop/ui/views/notifications/notification-permission . Сертификат не объявляется причиной, постоянный ключ сохранён.

## Проверки

JVM: LocalReplyProtocol (реальные TL entities, смещения emoji/форматирования, независимость wire, вложенная цитата в тексте ответа); PermissionPolicy (API 22–36, full/partial/single type/revoke/regrant, notification states), LocalReplyPolicy (UTF-16/emoji, hash, body edit/prefix edit). Реальный SQLite: account/dialog/mode isolation, temp→server ID, restart, retry, два автора, несколько ответов и очистка оригинала. Это не тесты Android RecyclerView/свайпа/сервера.

На Android вручную: свайп и меню Reply, предпросмотр, текст/emoji/entities/фото с подписью, send/retry, переход и подсветка, reopen/restart, два аккаунта, группы/каналы/форумные темы, редактирование и пересылка, очистка исходника. Официальный Telegram: та же отправка должна остаться блок-цитатой с кликабельным правильным автором. Предыдущая 0.2.4 подтверждена владельцем как работающая; новая версия не считается проверенной владельцем автоматически.

Разрешения: fresh install, full grant, selected-only, только фото/только видео, update поверх старой APK, resume, встроенная галерея/внешний Photo Picker, уведомление, revoke/regrant, Android 14+. Без удаления приложения. На ADB-хосте:

```sh
bash scripts/permission-snapshot.sh > before.txt
adb install -r Tetogram-debug.apk
bash scripts/permission-snapshot.sh > after.txt
diff -u before.txt after.txt
```

Скрипт не меняет разрешений, не выводит сообщения/сессии. Runtime-диагностика по умолчанию выключена: private preference `tetogram_diagnostics/permissions`; при включении пишет только SDK и состояния разрешений в штатный FileLog. Доступ к private preference требует debug-инструментов, автоматически не включается. Все ручные сценарии пока NOT RUN.
