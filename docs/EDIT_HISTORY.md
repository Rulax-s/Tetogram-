# История редактирования — 0.4.0 / code209

Включение: Настройки → Tetogram Labs → История редактирования → «Сохранять историю редактирования сообщений». По умолчанию выключено; первое включение требует отдельного согласия. Согласие на удалённые сообщения не используется автоматически.

Зажмите изменённое сообщение → «История редактирования»: полный старый текст, последняя сохранённая версия, автор, дата сообщения/правки и время локального сохранения. В Labs доступен выбор чата со списком его версий. При двух и более версиях рядом со штатным временем появляется отключаемая отметка «версии». Нативная отметка Telegram «изменено» сохраняется.

## Что действительно можно сохранить

Используются предыдущий native SQLite snapshot перед его перезаписью и новое MTProto-сообщение. После включения старый текст может быть доступен в кэше; если его нет, сохраняется только известная новая версия без фиктивного оригинала. Пропущенные версии не восстанавливаются массовой загрузкой истории. Последняя сохранённая версия не выдаётся за гарантированно актуальную серверную при выключенном сохранении или пропущенных обновлениях.

Обычные собственные правки поддерживаются после получения положительного ID. Секретные/TTL/самоуничтожение/одноразовые/ephemeral/protected/no-forwards, quick replies/welcome/scheduled и исключённые чаты не архивируются. Фото/видео/документы сохраняются как подпись и TL-метаданные; вложения автоматически не скачиваются. Отключение прекращает сбор новых версий, прежние удаляются отдельной очисткой.

## Архитектура

`EditHistory` добавляет таблицу `tetogram_edits_v1` в существующую приватную базу MessagesStorage аккаунта, без второго файла БД. Обе putMessages-ветки вызывают capture на storageQueue до native overwrite и обновления DeletedHistory snapshot. Штатные `updateEditMessage`/`updateEditChannelMessage` остаются в MessagesController и используют эту ветку записи. Ошибка локального архива не блокирует обработку Telegram.

Ключ — Telegram UID + dialog ID + message ID; у каждого snapshot собственные автор и TL payload. Локальный seq сохраняет порядок нескольких правок в одну секунду, включая A → B → A. Сравнение с последним состоянием исключает дубли повторных событий и откат на меньший edit_date. `EditHistoryContent` сравнивает текст, entities и стабильный attachment ID; views/reactions/file_reference/web-page preview не создают ложных версий. Пара снимков сохраняется в savepoint. Для собственных optimistic edits отдельно учитывается native send_state: до локального overwrite сохраняется подтверждённый baseline, попытка/отмена/ошибка не объявляется новой серверной версией; после ACK используется retained baseline.

Сроки 7/30/90/без ограничения и исключённые чаты общие с локальной историей. Очистка edit ledger затрагивает только указанный UID/did/mid; native сообщения, deleted snapshots и сервер не удаляются. Применяются secure_delete/WAL checkpoint. Исключение чата также удаляет его edit ledger.

На UI приходят только counts или отдельно десериализованные snapshots для read-only экрана. LruCache хранит только UID/did/mid/count, без текста и MessageObject. ChatMessageCell не читает SQLite и не меняет исходное сообщение. Live event обновляет layout нужной строки; counts восстанавливаются пакетно при загрузке. Версии не вставляются в обычный массив messages и не меняют его сортировку.

## Проверки

JVM: `EditHistoryPolicyTest` и `EditHistoryContentTest` — переходы/повторы/same-second/неизвестный оригинал/mark/ключи/Unicode/entities/вложения/volatile metadata. Python `test-edit-history.py` выполняет буквальные SCHEMA/INSERT Java store на SQLite: перезапуск, авторы/аккаунты/did, retention/clear, rollback, сохранность native/deleted таблиц, Unicode. Source contracts проверяют реальные точки интеграции. Это не запуск Android SQLite JNI или живого MTProto.

Ручной Android checklist — агентом **NOT RUN**:

1. Включить с согласием; A → B → C: текущий C в чате, A/B/C с правильным автором в истории.
2. Личный чат, группа, канал, форум; разные авторы, одинаковые mid в разных did/аккаунтах.
3. Быстрые правки, A → B → A, повторная доставка/открытие/перезапуск: нет дублей и подмены. Своя правка фото/caption: успешная, отменённая, с ошибкой и retry; попытка не выдаётся за серверную версию.
4. Выключить сохранение/отметку; новые версии не добавляются, прежние доступны через меню.
5. Неизвестный оригинал: нет придуманного старого текста. Unicode, форматирование и captions сохранены.
6. Views/reactions/preview не создают версий; секретные/TTL/одноразовые/ephemeral/protected не сохраняются.
7. Очистить сообщение/чат/всё: отметки исчезли, native сообщения и другой аккаунт остались.
8. Светлая/тёмная тема, крупный шрифт, длинный текст, навигация/Insets; без изменений сообщений/Reply/сортировки.
