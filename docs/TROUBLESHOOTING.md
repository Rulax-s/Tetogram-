# Известные проблемы и диагностика

## Текущее состояние

ARM64 debug APK получена в успешном run 43415735775. На телефоне нет JDK, Android SDK/NDK и Android Studio; сборка выполнена в GitHub Actions. Firebase package, API-поля, Gradle-задача, конечные идентификаторы, подпись и native ABI проверены. Runtime-функции пока не тестировались: успешная сборка не подтверждает вход, push или звонки.

## Сеть и подмодули

При загрузке были временные ошибки `Could not resolve host: github.com`. Основной Git fetch завершился; необходимые подмодули после повторных загрузок получены и сверены с закреплёнными SHA. Повторять `git submodule update --init --recursive --depth 1 --jobs 2`, сохраняя полный лог. Вложенный QuickJS test262 намеренно пропускается согласно upstream `.gitmodules` (`update = none`): это тестовый набор, не исходники, используемые CMake. Не менять SHA подмодулей на их текущий HEAD ради обхода ошибки. Незавершённый checkout может временно показываться как изменённый gitlink; не коммитить его, пока SHA не совпадёт с upstream.

Ошибка `.git/shallow.lock: File exists` была следствием прерванного первоначального clone. После проверки отсутствия Git-процесса lock перемещён в `.git/shallow.lock.interrupted` для диагностики. Не удаляйте lock при работающем Git.

## Неполная конфигурация

`prepare-ci.py` и `validateTetogramConfiguration` сообщают имена недостающих параметров без значений. Настройте собственные Secrets из BUILD.md. Официальные google-services.json удалены из текущего дерева, gitignore защищает будущий локальный файл. Официальные публичные образцы всё ещё существуют в истории upstream — это не личные секреты владельца Tetogram.

Google Services plugin применяется к APK-модулю: он генерирует Firebase-ресурсы для `org.tetogram.messenger`. В библиотеке плагин убран, потому что её внутренний namespace остаётся `org.telegram.messenger` и не должен требовать Firebase-приложения с чужим package. Firebase SDK и GcmPushListenerService сохранены; это не отключение push-реализации.

## Ошибки сборки

Сначала скачайте artifact `Tetogram-build-logs`. Определите первый содержательный `Caused by`/ошибку компилятора, а не только финальный `BUILD FAILED`. Разделяйте ошибки конфигурации, DNS/репозиториев зависимостей, CMake/NDK и Java/resources. Исправляйте исходную причину, сохраняйте полный лог, повторяйте тот же вариант сборки. Не вырезайте шифрование, VoIP, JNI или media.

При нехватке памяти используйте 2 Gradle workers и ограниченный heap, как в workflow. Если disk full — проверьте размеры SDK/NDK/промежуточных native-файлов; не удаляйте пользовательские файлы телефона.

При `INSTALL_FAILED_UPDATE_INCOMPATIBLE` сравните подписи. Новый debug-ключ не обновляет старую установку. Используйте сохранённый DEBUG_KEYSTORE_BASE64; не удаляйте приложение автоматически, потому что удалятся сессии и локальные данные.

При ошибке установки рядом с Telegram проверьте package, resolved authorities, custom permissions и accountType из merged manifest и ресурсов. Совпадающие Java class names и обработчики tg:// не означают одинаковый package. Реальную совместную установку всё равно нужно проверить.

## GitHub account locked due to a billing issue

Run: https://github.com/Rulax-s/Tetogram-/actions/runs/43408428079 . GitHub не запустил даже source-checks; build помечен skipped. Отсутствие логов (`log not found`) здесь объясняется отсутствием runner. Это не ошибка Gradle и не повод отключать компоненты или менять API-данные. Владелец устранил проблему; последующие runner запустились. Если сообщение повторится, проверять GitHub Billing, а не менять исходники или Secrets.

Проверка GitHub-подключения дала 403 на создание blob несмотря на права аккаунта в repo metadata. Действующая CLI-авторизация нашлась в конфигурации Termux; её использование через GH_CONFIG_DIR позволило выполнить обычный Git push без копирования токена и без изменения глобальных Git credentials.

## Проверка authorities после компиляции

В run 43412734080 Gradle собрал APK, но первоначальная проверка providers по строкам `aapt2 dump xmltree` завершилась `Provider authority conflict` без диагностических значений. Проверка переведена на структурированный XML непосредственно из APK (`apkanalyzer manifest print`), с выводом только имён providers и authorities. Повторный run 43415735775 подтвердил, что все реальные authorities уникальны, а ошибка была в прежней проверке дампа. Требование уникальности сохранено: все authorities и собственные permissions должны начинаться с org.tetogram.messenger. Полный manifest и metadata не выводятся, чтобы не раскрывать настроенные ключи сервисов.

## 0.2.0: подмена локальных копий и перемещение ephemeral

В 0.2.0 найдены коллизия adapter stable ID при живой замене удалённых сообщений и неверное использование packed ephemeral ID при слиянии истории. Исправление — 0.2.1; детали и ограничения проверок в MESSAGE_INTEGRITY.md. Очистка локальной истории не является исправлением и приведёт к потере копий. Схема DB не меняется; при той же постоянной подписи обновление 0.2.0 → 0.2.1 должно сохранять данные. Агент не выполняет удаление приложения или истории. Фактическое обновление/регрессию нужно проверить на Android.

## Reply на локальную копию (0.2.2)

Цитата появляется при отправке, обычная Reply-панель до этого показывает исходное сообщение. Отменяется штатным крестиком. Для входящего медиа без подписи используется native обозначение типа, файл автоматически не прикрепляется.

Текст и фото/видео/файлы с caption поддержаны. Poll/contact/location/game/todo/invoice/rich article не имеют подходящего поля для такой текстовой цитаты: при local Reply показано явное уведомление, запрос не отправляется. Обычная отправка этих типов без local Reply не меняется. Лимит Telegram применяется к итоговому тексту/подписи вместе с цитатой; пользовательский ответ автоматически не обрезается. Подробности — DELETED_REPLIES.md.
