# Системные отступы экранов Tetogram — 0.3.1, versionCode 109

## Причина и исправление

`LabsPage` включал `SimpleActionBar`, но не регистрировал свой `UniversalRecyclerView` в `BaseFragment.getListViewForSimpleGlass()`. Поэтому `performCreateViewImpl()` пропускал настройку SimpleGlass: перенос header над содержимым, подключение прокрутки, fade и установку list margins/padding. Кроме того, отсутствовал `isSupportEdgeToEdge() == true`, который в `ActionBarLayout` разрешает установку listener `onInsetsInternal`. Оба hook теперь совпадают со штатным `NotificationsSettingsActivity`.

Порядок: `BaseFragment.performCreateViewImpl()` вызывает `createView()`, затем получает уже созданный `list` и подключает SimpleGlass. При создании и последующих WindowInsets updates штатный `setListViewParams()` учитывает реальные top/bottom insets и текущую высоту ActionBar. Отдельные фиксированные status-bar padding, собственный listener и глобальные изменения edge-to-edge не добавлены. Верхний и нижний отступы управляются одним native механизмом, без повторного сложения.

Исправление наследуют `LabsActivity`, `SectionsActivity` (управление, редактор раздела и локальной папки), `HistoryActivity`, `ExcludedChatsActivity`. Других самостоятельных BaseFragment/SimpleActionBar экранов в `ui/tetogram` нет. Диалог выбора чатов использует штатный `DialogsActivity`.

В `HistoryActivity` поиск раньше был абсолютным overlay у верхнего края, с ручным `list.setPadding(48dp)`, который SimpleGlass заменяет. Теперь это первая native custom-row списка высотой 48dp: она прокручивается со списком и получает те же системные отступы. Это высота поля, не компенсация статус-бара. Запрос восстанавливается при пересоздании View до установки TextWatcher. База, поиск в истории, Reply, сообщения и аккаунтные настройки не меняются.

## Автоматические проверки

`python3 scripts/check-settings-insets.py` — шесть **статических source-contract** проверок: регистрация списка, native lifecycle после createView, listener/reapplication Insets, наследование всех экранов, отсутствие overlay у поиска и ручных компенсаций. Запускаются в CI. Это не JVM layout tests и не Android UI-тесты. Также выполняются прежние source/localization/JVM/TL/SQLite/сборочные проверки и проверка APK.

Версия приложения остаётся 0.3.1, APP_VERSION_CODE повышен с 9 до 10 (afat APK 99 → 109). ApplicationId, постоянный сертификат и GitHub Secrets не меняются.

## Ручной Android checklist — NOT RUN агентом

Android UI/ADB в среде разработки недоступны. Успех компиляции не подтверждает визуальный результат. На Android 14 и новее выполнить следующую матрицу: светлая/тёмная тема × жесты/три кнопки × portrait/landscape.

1. Открыть Labs из Настроек: заголовок/Back полностью ниже системных значков; первый пункт ниже заголовка, без лишней пустой полосы. Сравнить с «Уведомления и звуки».
2. Прокрутить длинный список вверх/вниз: штатное glass/fade поведение, последний пункт доступен над системной навигацией.
3. Перейти управление разделами → редактор раздела → локальная папка; вернуться Back и жестом. Проверить отступы после каждого перехода и отмены жеста.
4. Открыть локальную историю: поиск виден под header как первая строка; ввод/очистка/результаты/загрузка следующей страницы; клавиатура и возврат к началу списка.
5. Перейти в чат и обратно в историю, повернуть устройство с введённым запросом; нет дубля поиска/двойного отступа или перекрытия Back.
6. Открыть исключённые чаты и штатный picker, вернуться; проверить нижний пункт списка.
7. Открыть/закрыть PhotoViewer кадрирования и вернуться в редактор раздела: системные отступы восстанавливаются. Обновить APK поверх предыдущей без удаления данных.
